# Build 117 investigation (2026-11-22)

Confirmed from the Build 116 runtime paths, before repair:

- `ContentView.destinationContent` does route Movies and Series through `KyroMediaSourceRoot` and the shared `KyroUnifiedBrowseView`. The provider catalog is not a separate screen. However, `LibrariesTabView.selectedTab` starts at `.recommended`. With no Silo library, `loadedContent` displays **No Silo libraries available** instead of mounting the unified `.library` grid. The provider sync can therefore run behind a screen the user cannot see.
- `KyroUnifiedBrowseView` restores Jellyfin, then configures `KyroUnifiedBrowseModel`; that model resolves linked, connected accounts and starts `ProviderCatalogMirror.sync`. This is an indirect, background sync, not a post-authentication sync. A newly connected account relies on view invalidation through `accountsRevision` and a visit to Movies/Series.
- `KyroJellyfinConnections.connect` links the authenticated Jellyfin user to `kyro.identity.active-profile-id`. Restore requires that same active local profile. Switching to an unlinked profile correctly removes that provider from the active grid; the setup view does not explain this.
- `ProfileSelectionViewModel` switches between local Kyro profiles and Silo profiles according to Silo sign-in. The local `IdentityStore` retains profiles across provider removal. An existing `Home` profile is retained legacy local data, not a Jellyfin identity or an automatic fallback created by this code. The existing create form does not validate local name/PIN before invoking the identity store; local creation can fail with a generic storage/PIN error. First-run setup then reads `profiles().first` rather than the just-created profile.
- `KyroJellyfinDetailView` fetches provider-qualified movie/series IDs and seasons/episodes. Episodes are text rows with no selectable detail. Jellyfin playback is explicitly disabled in the view. `JellyfinClient` is read-only; no stream or progress API exists on this branch. No separate completed Jellyfin playback branch is present in local or remote branch names or history inspected here.
- `SearchView` fans out to Silo and IPTV but not the Jellyfin catalog. `KyroHomeView` shows a provider setup panel, not connected Jellyfin media. These are independent remaining gaps.
- Labs launch configuration selects `KyroXLaunchBackground`, a flat color; the cinematic artwork is SwiftUI startup content. The Labs wordmark uses stable Kyro's 1825×498 proportions even though the X image is a different asset. Physical-device visual feedback cannot be reproduced without a device recording or approved run; sizing corrections need device confirmation.

This is source-level evidence, not proof of end-to-end device behavior. No app data was reset.
